# 课表分享与教务导入修复

本轮在已上线的手机弹窗基础上调整功能菜单宽度、左右内边距，并为弹窗标题留出可收缩的空间，关闭按钮固定在右边的 44px 触控区，标题长短和课程数量不再影响其横向位置。

## 分享

- 分享页签不生成请求。只有点击生成按钮才发送一次 POST，立即显示加载状态并阻止重复点击。同一份内容在当前页面复用已生成链接；8 秒超时后给出重试提示。
- 页面只展示 `/s/<7位ID>` 短链接，不再显示长口令，也不会在短链服务异常时把长链接作为结果展示。复制由单独的点击操作完成，适配手机剪贴板权限。
- 服务端保留原有 D1 `share_links` 表。生成采用一条 `INSERT OR IGNORE ... RETURNING id` 处理插入和 ID 冲突，过期清理放到 `waitUntil`，每次最多 100 行。接口请求体上限 44 KB，编码上限 40 KB。
- `/s/<id>` 只跳转到带 `shareId` 的短参数地址；前端通过 `GET /share?id=<id>` 读取内容。GET 和跳转均检查 180 天期限。旧数据库记录、VOYRA1/2 口令、旧长链接继续兼容；新编码 VOYRA3 保留分隔符、备注、全部时段和作息设置。
- 接收者先预览，点击「下载并保存」后自动合并进自己的课表。未登录时打开站内登录，登录完成后自动继续保存，无需第二次确认。每个新增课程分配接收者自己的 ID，使用接收者的用户存储键和云端账号，不建立指向分享者课表的可编辑引用。
- 重复下载按课程实际内容去重，已有课表和已有设置继续保留；空课表才采用分享中的开学日期与作息。双方随后可独立编辑。

## 数据保留

继续使用 `ClassScheduleData_<uid>` 和 `schedule-classes-v1`。保存前保留原始本机 JSON 到 `.original-v2`，第一次读取的非空云端记录另存 `.cloud-original-v2`；课表备份导出包含这两份原始数据。数据损坏或本机存储失败时不会提示保存成功，也不会覆盖原文。

同步采用按课程 ID 的合并和可选 `_scheduleSync` 编辑/删除时间戳；空云端与迟到的读取不能抹掉新导入。2026-10-25 起，分页读取当前账号同一同步键的全部版本，每个浏览器只写自己带设备标记的云端行，兼容并保留历史重复行，避免两个设备同时覆盖同一行。原始云端版本保留在本机 `.cloud-rows-v1`（最近 8 份）并随备份导出。写入串行且检查当前账号和独立设备登录凭据；云端响应异常、本机损坏、请求超时或存储失败时停止覆盖并提示。

返回页面、恢复网络、同源课表变更以及前台每 30 秒自动读取更新；隐藏页面不轮询。常规同步在后台运行，不显示同步状态条和手动同步按钮；仅失败时显示重试或登录提示。手机和电脑使用独立设备会话，一端登录或退出不影响另一端。后台凭据失效时可在任意一端验证账号，其他有效设备会话自动恢复；设备自身到期需本机登录。退出只撤销本机登录凭据，保留本机数据。服务端统一处理 Bmob 会话并强制账号归属与私有 ACL，详见 [多设备登录](DEVICE-SESSIONS.md)。不同网站的本机存储仍各自独立：旧的未上传数据必须在原设备、原网址打开新版页面才能合并上传。底层不是服务端事务，不声称跨设备强一致性；并发修改按已有课程时间戳合并。

## 教务导入

2026-10-26 起默认采用网页版免安装流程：选择湖南人文科技学院及校园网 / 校外 VPN 入口 → 在学校官网登录，导出或复制课表 → 回本站识别、核对并保存。不要求安装 Tampermonkey 或导入助手；旧的 `eduSetup=1` 链接也进入此流程。学校账号密码只在学校页面填写，本站不读取学校登录状态，不显示无法核实的登录成功或逐周扫描进度。

文件与粘贴在同一个面板中切换。文件支持 .xls/.xlsx、保存的 .html/.htm、制表符 .txt/.tsv，最大 8 MB；兼容部分以 HTML 内容保存的 .xls 和 GBK/GB2312 文本，Excel 逐个工作表处理，并保留合并单元格。实际读取文件、已处理工作表数会显示进度；文件本身不上传，只在确认保存后同步识别出的课程。

识别支持网格与有列名的清单、教师、教室、单双周和零散周次。每门课必须有明确周次；缺失周次、非法星期/节次、超出 1–20 周或任一工作表解析失败时不给出半份结果，不默认猜成 1–16 周。预览显示来源、课程及源文件中实际出现的上课周次；这些周次不是对学校全部周次的扫描证明，界面明确按周导出的文件只有对应周的课程。

用户核对后确认合并。保存前重新读取本机课表、检查当前账号、分配接收账号自己的课程 ID，并按实际课程内容去重。原有课表、设置、备份与云端数据结构保留。异步文件/剪贴板读取绑定账号和本次面板，切换账号、切换页签或关闭面板后，旧读取结果不会落到新账号。

已有 3.0.0 助手的任务回传仍兼容，带合法 `eduImport` 的返回地址继续接收完整结果；显式 `eduAssistant=1` 仅用于旧流程兼容与回归，普通入口不展示安装步骤。已有助手的读取租约、断点、完整周次检查和串行合并保留。

普通网页受[浏览器同源策略](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Same-origin_policy)限制，无法直接读取学校域内的已登录课表。学校入口保持既有地址；校园真实网络和登录后的页面需由用户在自己的设备上访问，测试不使用真实学生账号。

## 验证

- `npm run test:education:web:data`：清单与网格、缺失/非法周次、全部工作表成功后才返回结果、多行文本与旧编码。
- `npm run test:education:web:ui`：5 个手机/电脑尺寸，默认免安装与旧设置链接、入口选择、文件/粘贴、拒绝半份结果、账号切换和合并保留旧数据；使用模拟学校页面与隔离账号。

- `npm run test:schedule:import:data`：编码兼容、账号隔离、幂等合并、旧数据保留、延迟同步、TSV/周次解析和真实 SQLite SQL/短链接口。
- `npm run test:schedule:import:ui`：先运行 `npm run build` 和 `npx wrangler pages dev dist --ip 127.0.0.1 --port 8789 --persist-to output/playwright/schedule-import-v2/d1`。使用真实本地 Workers/D1 验证生成、短链跳转、已登录下载、模拟登录后自动保存、重复下载、教务导入和手机布局。
- `npm run test:schedule`：保留原来的全部课表弹窗回归。
- `npm run test:schedule:sync:data`：多设备并发、旧重复行、分页、错误响应、本机损坏、账号切换和只读刷新。
- `npm run test:schedule:sync:ui`：先构建，再用两个独立网站来源、真实打包页面与设备会话处理函数，使用隔离 SQLite 和每次登录轮换凭据的后台模拟，验证手机/电脑双向同步、失败重试、同账号重新登录、注册凭据与退出/过期保留本机数据；不替换页面 API、不写真实账号。
- `npm run build:education`：使用共享解析、校验模块打包独立用户脚本；dev/build 自动生成，`node build-tools/build-education-helper.mjs --check` 可检查产物一致性。
- `npm run test:education:data`：真实网络失败/超时/登录可达判定、取消、精确周次合并、任务来源和有效期。
- `npm run test:education:ui`：生产 CSP/COOP 下的真实 Chrome 与两个模拟学校来源；GM 授权 API 用本机测试适配模拟，验证登录不被打断、逐周失败及续读、完整学期、当前账号确认保存、跨账号阻断、刷新恢复、5 个尺寸安装与手动入口。并未用真实学生账号登录学校。
- 所有测试账号与课表均为独立浏览器上下文中的假数据，云端账号写入被模拟，不接触真实用户课表。
