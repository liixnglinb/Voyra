# 血压记录改版

手机优先的血压记录页面：最近读数、独立血压/心率趋势、可搜索的历史记录、底部录入入口。录入与编辑共用弹层，日期和时间分开选择，保存按钮固定在底部，键盘出现时内容区滚动。桌面总览采用两栏。

## 原有数据兼容

- 本机键仍为 `userKey('HealthBpData')`，云端键仍为 `health-bp-v1`，账号之间继续隔离。
- 同时读取旧版直接数组和 `{ records: [...] }`。不会把示例读数写入新账号。
- 记录的 `id / sys / dia / hr / time / period / note` 保持原义；修改时保留未知字段，读取时不改写时间和读数。
- 合并使用稳定的记录 ID；旧数据同 ID 内容不一致时保留副本。显式修改和删除使用可选 `_healthSync` 元数据，`records` 仍兼容旧版。
- 云端空结果不能抹除本机记录。读取失败时不向未知的云端记录集上传覆盖；本机写入成功后才提示保存，云端失败显示重试状态。
- 云端请求在当前页面内串行，保存前重新读取合并，并核对当前账号。保存期间发生的新录入会继续同步。
- 后端仍是原有整份文档接口，没有服务端事务/CAS；不同设备完全同时写入仍受该接口约束。保留各自本机记录，下次读取会继续合并。没有声称支持强一致同步。

## 备份与恢复

首次改写本机之前将原文保存在 `${userKey('HealthBpData')}.original-v1`，该备份不覆盖；首次读取的非空云端结果另存 `.cloud-original-v1`。编辑、删除、导入和同步前保留最近 8 个恢复快照 `.recovery-v1`。备份无法写入时中止后续写入。

完整 JSON 导出包含当前全部记录、同步信息、原始本机/云端备份和恢复快照。界面可选择历史快照进行合并恢复。JSON 导入兼容旧数组，先显示新增/重复/冲突数量，再由用户确认合并；不会应用导入文件中的删除标记。CSV 适合表格查看，完整恢复应使用 JSON。

删除需确认，并提供 20 秒撤销；之后仍可在恢复历史备份中找回。取消了原先直接覆盖记录的“恢复示例数据”。格式异常的本机原文不覆盖，可通过完整备份导出排查。

## 读数与趋势

收缩压/舒张压共用 mmHg 轴，心率单独使用 bpm 轴；纵轴根据真实读数调整，取消旧版 165 的截断。点按/拖动或前后按钮可查看某次实际读数；均值按所选次数范围计算。次数范围保持近 7 次、近 14 次和全部。

移除从单次测量给出疾病分级和“达标率”的界面，改为描述读数与家庭参考线 135/85 mmHg 的关系。低于参考线不代表一定正常。展开说明链接到[国家卫健委家庭血压测量说明](https://www.nhc.gov.cn/jkj/c100063/202009/b6a4c154c6574ed6814c15010c8b4b94.shtml)，诊断需多日规范测量与医生评估。

## 验证

```sh
npm run build
npm run test:health:data
npm run test:health:ui
npm run test:ui
```

数据测试覆盖旧格式、未知字段、初始备份、空云端、冲突副本、迟到的云端读取、串行保存、离线重试、账号切换、损坏 JSON、配额失败、恢复和导入导出。浏览器使用独立上下文和本地模拟 API，阻断外部网络，不接触真实用户数据。

生产构建使用站点 CSP 检查 320/360/390/430 宽手机、844×390 横屏、768 平板与 1440 桌面；另检查键盘缩小视口、焦点与登录守卫。截图和测试报告位于忽略目录 `output/playwright/health-log/`。这些是 Chrome 的移动尺寸检查，尚未在实体 iOS/Android 设备上执行。
