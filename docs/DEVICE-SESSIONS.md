# 多设备登录与同步

实测当前 Bmob 后台在同账号重新登录后会使之前的会话失效，旧设备访问私有记录返回 122。GET、POST 登录均复现。网站通过独立设备会话解决此问题，不依赖放开私有 ACL，也不保存用户密码。

## 会话流程

- 浏览器通过同源 `/auth` 登录或注册。服务端验证账号后生成 32 字节随机设备凭证，只将其 SHA-256 摘要保存到 D1 `voyra_device_sessions`，有效期最多 30 天。
- Bmob 会话仅保留在服务端。`/cloud-data` 验证设备凭证，并选用同账号最近的有效 Bmob 会话；遇到会话失效时重新读取凭据，处理另一端登录与同步重叠的情况。
- 每台设备的凭证独立，退出或重新验证只撤销本机的旧凭证。已退出设备产生的 Bmob 凭据可继续由其他有效设备会话使用，因此不会使其他设备离线。
- 不保留密码，也无法在所有 Bmob 凭据过期后凭空续期。任意一端验证账号可为仍有效的其他设备会话恢复后台同步；设备自身到期后需要在该设备登录。
- 旧版仍有效的 SDK 会话可验证后交换成设备会话；已经失效的旧会话需要验证一次账号。不能根据本机声称的 UID 直接发放权限。

## 数据与部署

原有 Bmob 应用、`user_data` 表、账号 UID、课表键、按设备写入的历史版本以及本机备份均保持兼容。登录不执行原先按 180 天未活动自动删除用户记录的操作。退出只删除登录凭据，保留本机业务数据。

服务端强制记录属于当前验证账号，并强制私有 ACL；更新与删除前检查记录归属。课表历史版本不支持整表删除。请求有来源校验、体积限制与超时，响应不缓存，不返回后台会话或原始诊断信息。

Cloudflare Pages Functions 需要现有 D1 绑定 `DB` 和已有环境变量 `VITE_BMOB_APPLICATION_ID`、`VITE_BMOB_REST_API_KEY`。首次请求仅新建独立会话表与索引，不迁移、重建或删除业务表。海外 EdgeOne 的 `/auth`、`/cloud-data` 转发到原 Cloudflare 服务，与正式域名共享账号和云端数据。`GET /auth` 的 `ready` 可检查必要绑定是否齐全。

## 验证

- `npm run test:session:data`：真实处理函数与内存 SQLite，模拟每次登录强制轮换后台凭据，验证双设备、单端退出、并发登录重试、旧会话交换、权限隔离与安全错误。
- `npm run test:schedule:sync:data`：课表历史版本、分页、合并与本机备份。
- `npm run test:schedule:sync:ui`：生产构建页面、手机与电脑独立浏览器来源、真实设备会话处理函数、隔离后台，验证真实登录表单、双向添加、单端退出以及本机数据保留；不会写入真实账号。
- `npm run test:edgeone:proxy`：两种设备会话路由保留认证、来源与请求内容，并禁止缓存。

线上验证应使用专门创建的临时账号与测试记录，完成后只清理该账号拥有的测试数据，不用真实用户的数据作写入测试。
