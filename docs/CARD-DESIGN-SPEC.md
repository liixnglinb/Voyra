## 实现约定

- 保持原有 DOM 布局：分类眉标 → 品牌与标题 → 说明 → 入口；装饰编号保留原位置。
- 每张卡使用浅色卡面、较深的主题文字、同色系插画背景；正文统一深灰。
- 用户要求直接原位替换：列表间距、卡片宽高、圆角、内边距、左右交替与响应式断点完整沿用改版前的 dashboard-cards.css。
- 原版主卡 min-height 304px、列表 gap 20px、内边距 28px / 34px、桌面两栏 gap 36px；860px 以下沿用原版单列。真实高度由原版内容计算，不另设新尺寸。
- 移动端短说明继续走 APP_SHORT；插画绝对定位在原舞台内，不能反过来撑高卡片。
- 配色集中于 src/data/card-illustrations.js；矢量插画集中于 src/components/CardIllustrations.jsx。
- 卡片样式集中于 src/styles/showcase-cards.css，在旧舞台样式之后加载。
- src/styles/dashboard-cards.css 已恢复改版前版本，完整负责原卡片几何；showcase-cards.css 只覆盖配色、插画与动效。
- 不改 SHOWCASE_GROUPS、路由、外链新标签页约定与 ProductCard props；隐藏的历史卡仍支持 STAGES 兜底。
- 插画不依赖外部生成图片；示例指标沿用 card.stage，整个图形区 aria-hidden。
- 插画进入视野后循环播放各自的功能动效：请求传输、周历编排、浮卡、心跳与心电线、建模曲线、签到打勾、清扫、收据入库、用量图表和日志。
- 悬停叠加轻抬升、视差与箭头反馈；触屏保留插画动效并禁用倾斜。减少动态效果设置禁用动画与过渡，插画保留完整静态终态。
- 动效使用 CSS 的独立 translate / rotate / scale、opacity 以及 SVG 描线，不触发布局；独立变换不能改写插画已有的 SVG 旋转基准。
- useCardEffects 以浏览器视口观察可见性，离屏与后台页面暂停；直接在实际首页原位替换卡片，旧总览链接跳回首页。
- 保留键盘聚焦轮廓及强制颜色模式中的显式边框。正文、分类和 CTA 对所在底色的对比度均须 ≥ 4.5:1。

# 历史记录：Voyra 展示卡设计规范 v2

> 写在最前面的话：这张卡**不是**「一个大标题 + 一张贴图」。
> 它是**一张名片**：读者在三秒内要知道「这是什么、我能不能用、点了会发生什么」。
> 舞台上的一切元素都必须服务于这个判断，不能为了「画面丰富」而堆。

---

## §0 一句话设计原则

**一张卡 = 一个视觉锚点 + 三级文字层级 + 一行元信息 + 一个动作。**
多一个元素都是负担，少一个元素都是缺陷。

---

## §1 为什么重做（v1 的七个具体缺陷）

| # | v1 的问题 | 现象 | v2 的解法 |
|---|---|---|---|
| 1 | 舞台是内容黑洞 | 舞台占卡面 45%，内部只有 2~4 行内容，其余是死白/死黑 | 舞台内容密度下限提升：至少 4 个可读元素；不够就换舞台画面 |
| 2 | 文字栏被挤到 285px | 描述 2 行 clamp 后断句破碎 | 文字栏改 `minmax(0, 1.05fr)`、舞台 `minmax(0, 1fr)`，描述取消 clamp 改自然换行 + 最多 3 行 |
| 3 | 标题 40px 在全宽卡里失控 | 8 字标题（如「学习通自动签到助手」）视觉过重 | 标题 `clamp(26px, 2.6vw, 34px)`，weight 700，字距 -0.02em |
| 4 | 没有 Meta 行 | 卡片只有标题+描述+CTA，读者不知道平台/形态 | 新增 `.sc-meta` 行：3 个 dot-separated 标签（平台 / 形态 / 状态） |
| 5 | 42px 空心序号是纯装饰 | 占左下角，与 CTA 争重心，信息价值为零 | 删除序号元素；编号并入眉标（`01`）已经足够 |
| 6 | ink 基调舞台纯黑过硬 | 黑卡贴在米白卡上像贴纸 | ink 舞台底从 `#141311` 提到 `#1F1E1C`，面板提到 `#3A3835`，降低对比冲击 |
| 7 | 卡片高 344px 但内容仅占 65% | 底部大片空白显得「空」 | 高度改 `min-height: 268px` + 内容垂直居中 + 内边距加大到 28/32px |

## §2 色彩系统（不可新增色相）

### 2.1 卡壳（固定，不随 tone 变）

```css
--sc-surface:   #FFFFFF;   /* 卡面：纯白 */
--sc-border:    #E8E8E8;   /* 1px 描边，与参考站一致 */
--sc-text-main: #1A1A1A;   /* 标题 */
--sc-text-sub:  #666666;   /* 描述（对白 5.74:1，过 WCAG AA）*/
--sc-text-dim:  #8A8A8A;   /* Meta / 眉标小字（只用于 12px 以上）*/
```

**边框不用 `border`，用 `box-shadow: 0 0 0 1px`**（Vercel 规范）。
理由：CSS border 会参与盒模型计算并与 `border-radius` 叠加出锯齿，box-shadow 的描边永远在圆角外侧平滑收口。

### 2.2 四色调（tone）—— 只允许这四组

| tone | 用途 | accent | 舞台底 | 舞台面板 |
|---|---|---|---|---|
| `ink` | 最重的一档 | `#8A6D1F` | `#1F1E1C` | `#3A3835` |
| `gold` | 全站基准 | `#8A6D1F` | `#F7F1E2` | `#FFFCF3` |
| `blue` | 唯一冷色 | `#1F5FE0` | `#EDF1F8` | `#FFFFFF` |
| `paper` | 最克制 | `#1A1A1A` | `#F4F2ED` | `#FFFFFF` |

对比度硬门槛（`npm run cards:palette` 自动校验）：所有文字对底 ≥ 4.5:1，所有图形对底 ≥ 3:1。

### 2.3 颜色纪律（component-taste.md 的硬规则）

- ✅ 颜色**只出现在卡内**：点睛的色点、图标、舞台、CTA 悬停。
- ❌ 禁止在圆角卡上放**彩色顶边**（直线与圆角打架）。
- ❌ 禁止每张卡一种色相 —— 差异靠 tone×画面，不靠色相数量。
- ❌ 禁止饱和渐变背景。

## §3 排版层级（这是 v2 最重要的一节）

一张卡从上到下**严格四层**，字号与字重必须形成明显落差：

```
[Meta 行]      11px / 600 / mono / letter-spacing .06em / #8A8A8A   ← 最弱
   ↓ gap 14px
[眉标]         12px / 500 / #666 + 5px 色点                          ← 弱
   ↓ gap 10px
[标题]         clamp(26px,2.6vw,34px) / 700 / -0.02em / #1A1A1A      ← 最强
   ↓ gap 12px
[描述]         15px / 400 / 1.75 / #666 / 最多 3 行                   ← 中
```

**Meta 行放什么**（必须有，3 个标签，dot 分隔）：
平台（Web / Windows）、形态（云端 / 本地）、状态（在线 / 每日更新）。
数据源：`src/data/showcase-cards.js` 新增 `meta: ['Web', '云端', '在线']`。

**为什么加 Meta**：
GitHub 的 component-patterns.md 给出标准卡片结构：

```
┌─────────────────────────┐
│ [Icon]  Title           │
│ Description (2-3 行)    │
│ Meta · Meta · Meta      │  ← caption-style, dot-separated
└─────────────────────────┘
```

v1 缺的正是这一行 —— 卡片信息量不足、底部留空、读者判断不了产品形态。

**排版纪律（Vercel 规范）**：
- 标题靠**紧字距 + 中等字重**建立层级，不靠 700+ 的粗。
- 描述与标题的字号比必须在 2:1 以上，否则层级糊掉。
- 等宽字体只用于「盖章类」信息：眉标、Meta、舞台内的小字。正文绝不用 mono。

## §4 卡片几何

```css
.sc-card {
  min-height: 268px;          /* v1 是 300px，内容装不满 */
  border-radius: 20px;        /* 与参考站一致，不要更大（>24px 就成胶囊了） */
  padding: 0;                 /* 内边距交给 .sc-body */
  box-shadow: 0 0 0 1px #E8E8E8, 0 1px 2px rgba(22,19,14,.04);
  overflow: hidden;
  container-type: inline-size;
}
```

**内边距**：`28px 32px`（v1 是 22/26 —— component-taste 的第一条就是「慷慨的内边距，让内容呼吸」）。

**两栏比例**：
```css
grid-template-columns: minmax(0, 1.05fr) minmax(0, 1fr);  /* v1 是 1.15fr : 1fr，文字被挤 */
gap: 14px 36px;
```

**窄屏（≤960px）**：单列，舞台在上、文字在下，`padding: 20px 18px 24px`。
窄屏时 `.sc-seq` 移到右下角（v1 已做，保留）。

## §5 深度（Elevation whispers）

open-bridge 的原话：**「Never stack shadows, add inner glows... Elevation whispers.」**
Vercel 的三层叠加是上限，不是起点。

```css
/* 静止 */
box-shadow:
  0 0 0 1px #E8E8E8,
  0 1px 2px rgba(22,19,14,.04),
  0 8px 20px -14px rgba(22,19,14,.14);

/* 悬停：只加远影，不加近影；位移与投影用不同时长制造重量差 */
box-shadow:
  0 0 0 1px #D5D5D5,
  0 2px 4px rgba(0,0,0,.04),
  0 26px 48px -18px rgba(0,0,0,.16);
transform: translateY(-4px);          /* v1 是 -6px，-6 在 268px 高的卡上过于明显 */
transition:
  transform .45s var(--vr-ease-out),
  box-shadow .7s  var(--vr-ease-out),
  border-color .7s var(--vr-ease-out);
```

**为什么位移 .45s 而投影 .7s**：位移先到（跟手），投影后到（重量感）。
两者同速会看起来像「整块弹了一下」。这是参考站实测的做法。

## §6 舞台（Stage）—— v2 的重点重灾区

### 6.1 舞台存在的理由

舞台不是装饰，是**「这个产品长什么样」的证据**。判断标准只有一条：
> 把舞台盖住，这张卡还成立吗？如果成立，说明舞台是装饰，必须重画。

### 6.2 硬性要求

| 项 | 要求 |
|---|---|
| 内容密度 | **至少 4 个可读元素**（表格行 / 列表项 / 按钮 / 数值）。少于 4 个就是浪费 45% 的卡面 |
| 溢出 | 任何子元素不得超出舞台边界（`cards:verify` 自动校验） |
| 内边距 | `18px 20px`，行间距 ≥ 7px |
| 材质 | 「纸片」而非「色块」：`--stg-panel` 底 + `rgba(--stg-ink-rgb,.10)` 描边 + 1px 内高光 |
| 分隔线 | `rgba(--stg-text-rgb,.07)` + 下一行补一道 `rgba(255,255,255,.55)` 内高光（折痕感） |
| 动效 | 入场 stagger ≤ .05s/项，缓动 `cubic-bezier(.19,1,.22,1)` |

### 6.3 网格陷阱（v1 真实踩过）

课表舞台的星期表头与课程格子曾**重叠 7px**：课程 `grid-area: 1/x/3/y` 与表头 `grid-row: 1` 撞在同一行，
后画的课程纸片把表头盖掉。

**规则**：
- 网格里如果有「表头行 + 内容行」，内容行的 `grid-area` 必须从第 2 行开始（`2/x/4/y`）。
- 表头要**同时**钉死 `grid-row` 和 `grid-column`，只钉行会让五个标签挤进第 1 列。
- 每次改舞台网格后必须跑 `npm run cards:verify` 看 `stageIntegrity.problems`。

### 6.4 表格类舞台的排版规则

- 中文标签**最小 11px**，低于 11px 在真机上会糊成一团。
- 中文课名/条目**禁止从词中间折行**：`word-break: keep-all`。
- 格子内容超过 4 个汉字就换画面，不要靠缩字号解决。

## §7 悬停微交互（参考站实测值，全部保留）

| 元素 | 效果 | 时长 |
|---|---|---|
| 卡面 | 上移 -4px + 远影 | .45s / .7s |
| 图标盒 | `rotate(-4deg) scale(1.06)` + 反色填充 | transform .65s，背景 .35s |
| 标题 | 底部金色高亮从左扫入（`background-size: 0 42%` → `100% 42%`） | .6s |
| CTA 箭头 | `translateX(6px)` | .7s |
| 金色光斑 | 指针跟随，`radial-gradient(190px, rgba(255,226,138,.4), …)` 淡入 | .45s |

**金色光斑的关键教训**：第一版用了卡片强调色 `--p-rgb`，结果 ink/paper 基调渲染成一团**深灰**，
在白卡上像污渍。必须用**浅金 #ffe28a**（打亮，不是压暗），它对四种基调都成立。

## §8 无障碍与降级

| 场景 | 要求 |
|---|---|
| 整卡可点 | `<a>` 包住全部内容，**不要**只在角落放一个小链接 |
| 外链 | `target="_blank" rel="noopener noreferrer"` |
| 舞台 | `aria-hidden="true"`（纯装饰，文字不承载信息） |
| 焦点 | `outline: 2px solid #1A1A1A; outline-offset: 4px` |
| `prefers-reduced-motion` | 全部 transform/transition 归零，舞台保留终态 |
| `forced-colors` | 边框改 `CanvasText`，描边数字改 `CanvasText` |
| 触屏 | `@media (hover: none)` 下禁用光斑，`:active` 给 -2px + .12s |
| 对比度 | 文字 ≥ 4.5:1，图形 ≥ 3:1，`npm run cards:palette` 自动校验 |

```text
你要重做 Voyra 个人网站（React 18 + Vite + Tailwind，纯 CSS，无 UI 框架）
首页「产品 / Skills / 应用」三区的展示卡。请严格按下面的规范执行，
不要引入任何组件库、动画库或渐变。

【卡片结构】（自上而下，顺序不可调换）

5. CTA：14px / 500 / #666，右上箭头图标，悬停变 #1A1A1A 并右移 6px

【几何】
- 卡片宽 746px（单列全宽），最小高 268px，圆角 20px，白底
- 内边距 28px 32px（窄屏 20px 18px 24px）
- 两栏：文字 minmax(0,1.05fr) | 舞台 minmax(0,1fr)，列间距 36px 行间距 14px
- 偶数卡舞台换到左侧（nth-child(even)）
- 窄屏（≤960px）单列，舞台在上文字在下

【深度】
- 描边不要用 border，用 box-shadow: 0 0 0 1px #E8E8E8
- 静止阴影：0 1px 2px rgba(22,19,14,.04), 0 8px 20px -14px rgba(22,19,14,.14)
- 悬停：上移 4px，投影换成 0 26px 48px -18px rgba(0,0,0,.16)，描边加深到 #D5D5D5
- 位移 .45s、投影 .7s，统一缓动 cubic-bezier(.19,1,.22,1)——时长不同是刻意的

【颜色】
- 卡片外壳恒定：白底 + #E8E8E8 描边 + #1A1A1A 标题 + #666 描述 + #8A8A8A 元信息
- 只允许四种基调：ink / gold / blue / paper，强调色分别是
  #8A6D1F / #8A6D1F / #1F5FE0 / #1A1A1A

【舞台】（卡内的产品预览，v2 的重点）
- 舞台不是装饰：盖住它这张卡就不成立，说明画面不合格，必须重画
- 内容密度下限：至少 4 个可读元素（行 / 项 / 按钮 / 数值），少于 4 个就是浪费卡面
- 材质用「纸片」不用「色块」：面板底色 + rgba(ink,.10) 描边 + 1px 内高光
```

# v4 补充：为什么「回到参考站」是对的选择

用户连续三次反馈卡片「还是不行」，v2 加了 Meta 行、v3 加了顶部品牌带，
每次都在往卡里**加**东西 —— 这是错的方向。

## v4 的实测对照（Playwright 取值，1440 视口）

| | 参考站 oiloil.org .pcard | 本站 v3 | 本站 v4 |
|---|---|---|---|
| 卡片尺寸 | 756 × 300 | 746 × 344 | 746 × **300** |
| 圆角 / 内边距 | 20px / 22 26 | 20px / 28 32 | 20px / **22 26** |
| 两栏 | 356px : 310px, gap 36 | 1.05fr : 1fr, gap 36 | **1.15fr : 1fr, gap 36** |
| 文字栏内容 | logo + 标题 + 描述 + CTA | 品牌带 + 眉标 + logo + 标题 + 描述 + Meta + CTA | **logo + 标题 + 描述 + CTA** |
| 舞台 | 356×200 产品界面缩略 | 数据看板（行+条形+流水） | **产品界面缩略** |
| 序号 | 42px 空心描边，bottom 18 left 28 | 已删除 | **恢复** |

## 三条硬结论

**① 参考站没有的东西，不要自己加。**
Meta 行来自 GitHub 的 `component-patterns.md`（「Meta · Meta · Meta 是必备行」），
但那是**通用列表卡**（头像/缩略图 + 标题 + 描述 + 标签 + 操作）的结构，
套到「横向大卡 + 产品演示」上就是过载。规范要按形态选，不能照搬。

**② 序号不是信息，是压角。**
v2 以「信息与眉标重复」为由删掉它，是误判。参考站的 CTA 左对齐，
左下角留着一块安静空白，42px 的空心数字填在那里 —— 它的职责是
**平衡视觉重心**，不是传达编号。删掉之后卡面左下空、右下空，读着「没做完」。

**③ 舞台应该是产品界面，不是图表。**
参考站的舞台分别是插画、编辑器、设置面板、搜索结果页 ——
没有一个是图表。而本站 19 张卡的舞台全是「数据行 + 进度条」的看板形态，
进度条更是图表专属语汇（真实产品里没有「数据热度条」）。
v4 把 VoyraAI 两张卡重画为商城首页缩略（搜索栏 + 2×2 商品格）
与推荐页缩略（推荐码横幅 + 2×2 类目格）。

## v4 后不可再犯的三条

1. **改 `.sc-body` 的列结构时，同步检查子元素的 grid 归属。**
   v4 把三行网格改成两列，忘了 `.sc-foot`（CTA）还是 `.sc-body` 的直接子元素，
   自动放置把它排到了第二行，卡片从 300px 撑到 377px。
   现在 CTA 在 `.sc-copy` **内部**（与参考站 `.pinfo` 一致）。

2. **删掉 `gap` 就要补 `margin`。**
   删 `.sc-copy` 的 `gap:14px` 后忘了给 `.sc-foot` 加 `margin-top`，
   实测描述底边与 CTA 顶边重合（间距 0），两行字糊成一坨。

3. **卡片 min-height / 舞台 min-block-size / 内边距三者联动。**
   改任何一个都要重算另外两个，否则同行卡片高度参差。
   v4 的组合：卡片 300px + 内边距 22/26 + 舞台 min 200px = 四卡齐 300px。
